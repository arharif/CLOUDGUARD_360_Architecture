Questions fréquentes & résolution d'incidents

Erreur « OWNER/cloudguard360-phase04 »

OWNER était un exemple. Ce package utilise votre vrai dépôt NabilNet/cloudguard360-phase04. Vérifier avec gh repo view.

Erreur « Expected official sample main.py not found »

Le bon chemin est azure-vote/azure-vote/main.py dans le dépôt Microsoft. Le package vérifie main.py, templates, static et config_file.cfg, et s'arrête avant tout push si la structure change.

Erreur AADSTS700213 / sujet OIDC non reconnu

Depuis juillet 2026, les nouveaux dépôts peuvent utiliser le sujet immuable repo:OWNER@ID/REPO@ID:environment:... . Le workflow 00 obtient le sujet réel, puis Terraform crée exactement la correspondance.

Image GHCR privée ou échec de « docker pull »

Ouvrez GitHub Profile → Packages → cloudguard360-vote → Package settings → Change visibility → Public. Le workflow de déploiement refuse de continuer si le pull anonyme échoue.

AuthorizationFailed dans Azure

Les droits de création d'une identité gérée et d'une affectation RBAC ne sont pas garantis. Demandez une approbation à un administrateur habilité ; ne contournez pas le contrôle d'accès.

La Phase 03 Terraform veut remplacer mon image

Exécutez le contrôle reconcile après la mise à jour de l'app. Il sauvegarde puis met à jour uniquement frontend_image dans terraform.tfvars, et lance terraform plan sans appliquer.

La Phase 04 est-elle prête pour la production ?

Non. C'est un laboratoire public. Le scan CVE reste informatif, le frontend écoute sur le port 80 dans le conteneur, le rôle Container Apps Contributor est large et Redis est non persistant. Ne pas y placer de données sensibles.
